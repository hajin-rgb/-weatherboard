## 된 기능과 확인 결과

‘완료’는 사용자가 직접 확인한 항목에만 사용합니다. 자동 테스트와 코드 구현만 확인된 항목은 ‘미확인’으로 남깁니다.

| T-번호 | 기능 | 사용자 확인 결과 | 개발 중 검증 |
| --- | --- | --- | --- |
| T-01 | DB의 기본 가상 일정 6건 표시 | 미확인 — 정확히 6건이 보이는지 별도 확인 필요 | 실제 wx_tasks 공개 조회 HTTP 200 확인 |
| T-02 | 일정 추가 및 DB 저장, 새로고침·다른 브라우저에서 유지 | DB 저장 완료 — 사용자가 저장 성공 확인. 새로고침·다른 브라우저 조회는 미확인 | 모의 응답으로 조회·추가 및 실패 처리 확인 |
| T-03 | 세종·대전·태안·보령의 오늘 날씨와 판단 표시 | 미확인 | Open-Meteo 실제 응답과 풍속 m/s 단위 확인. 지역별 예보 수치는 같을 수도 있음 |
| T-04 | ?test=wind에서 고소 일정 2건 중지 검토 표시 | 미확인 | 모의 응답에서 풍속 12m/s와 고소 일정 판단 확인 |
| T-05 | 오늘 판단을 마크다운 표로 다운로드 | 미확인 | 생성 함수의 표 내용·특수문자·판단 기준 테스트 통과. 실제 다운로드는 미확인 |
| T-06 | 허용하지 않는 지역·구분을 DB에서 거부 | 미확인 | setup.sql에 CHECK 제약 작성. 실제 거부 실행 결과는 미확인 |

추가 구현: 제목 아래 날짜 표시, 날씨 재조회 버튼·수신 시각, 기상청 현재 관측 표시. 사용자 화면 확인은 미확인입니다.

## 알려진 문제와 제한

- 정확한 Vercel 배포 주소를 README에 등록해야 합니다.
- 기상청 실황의 실제 키 인증과 배포 화면 수신은 미확인입니다. 실황은 현재 관측이며, 일정 판단은 Open-Meteo의 오늘 예보를 사용합니다.
- 다른 사람이 추가한 일정은 페이지를 새로고침해야 반영됩니다. 실시간 자동 갱신과 일정 수정·삭제 기능은 없습니다.
- 이전 localStorage의 추가 일정은 DB로 자동 이전하지 않습니다. data/tasks.json은 참고용으로 남아 있습니다.
- 로그인 없는 교육용 DB로 공개 조회·추가를 허용합니다. 실제 개인정보는 저장하지 않습니다.
- DB·날씨 API·supabase-js CDN 이용에는 인터넷 연결이 필요합니다. API 실패 시 안내를 표시합니다.

## 실행과 설정

1. Supabase SQL Editor에서 프로젝트 루트의 setup.sql을 실행합니다. 사용자는 실행했다고 확인했습니다. 새 환경에서는 빈 표에 가상 일정 6건을 넣습니다.
2. config.js는 Supabase 주소·공개용 publishable 키 두 줄입니다. secret/service_role 키는 사용하지 않습니다.
3. Vercel 서버 환경변수 key_publicdata는 기상청 실황 API에서 사용합니다. 추가·변경 후 재배포가 필요합니다.
4. 배포 주소를 열어 사용합니다. 기상청 서버 함수는 Vercel 배포 환경에서 동작합니다.

## 주요 파일

| 파일 | 역할 |
| --- | --- |
| index.html / style.css | 화면 구조와 디자인 |
| app.js | DB 조회·추가, 날씨 호출, 화면과 다운로드 동작 |
| logic.js | 날씨 주소·응답 처리, 판단 규칙, md 생성 |
| config.js | Supabase 주소·공개용 키 |
| setup.sql | DB 표·지역/구분 제약·조회/추가 정책·초기 가상 데이터 |
| api/current-weather.js | 서버에서 기상청 키를 읽어 실황 조회 |
| PRD.md / CLAUDE.md | 요구사항과 작업·데이터 규칙 |

md 저장 파일명은 현장일정_판단_YYYY-MM-DD.md입니다. 현재 표와 마지막 줄의 판단 기준을 저장하며, 강풍 테스트 중에는 테스트 결과임을 표시합니다.
