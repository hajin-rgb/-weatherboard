## 날씨 확인 (F-04)
- Vercel의 `key_publicdata` 환경변수를 서버 함수 `api/current-weather.js`에서 읽어 기상청 초단기실황을 추가 표시합니다. 키는 브라우저에 전달하지 않습니다.
- Production 환경변수 적용 후 재배포하세요. 현재 관측은 Vercel 주소에서 동작하며, 파일을 더블클릭한 경우에는 기존 Open-Meteo 예보를 사용할 수 있습니다.
- 기상청은 지역 대표 격자(세종 66/103, 대전 67/100, 태안 48/109, 보령 54/100)의 1시간 전 정시 관측을 조회합니다. 실황은 하루 최고 기온·최대 풍속·강수확률과 구분하고 기존 일정 판단에는 섞지 않습니다.
- 배포 확인: ‘현재 관측 · 기상청’에 4개 지역 수치와 관측 시각이 표시되는지 확인하세요. 키의 실제 인증과 배포 연결은 배포 화면에서 확인이 필요합니다.
- ‘날씨 다시 불러오기’로 페이지 이동 없이 재조회합니다. 조회 중에는 중복 요청을 막습니다.
- 날씨 옆의 ‘수신’은 해당 지역 데이터를 받아 온 시각이며, 기상기관의 예보 발표 시각과는 다릅니다.
- 재조회 시 이전 날씨를 지웁니다. 실패한 지역에 과거 판단이 남지 않는지 확인하세요.
- [Open-Meteo](https://open-meteo.com/en/docs)의 키 없는 API로 한국 시간 기준 오늘 예보를 가져옵니다. 인터넷 연결이 필요합니다.
- 표의 날씨는 최고 기온(℃) · 최대 풍속(m/s) · 최대 강수확률(%) 순서입니다.
- T-03: 페이지를 열어 4개 지역의 날씨와 판단을 확인합니다. 지역별 예보 수치는 같을 수도 있습니다.
- T-04: 주소 끝에 `?test=wind`를 붙여 새로고침합니다. 날씨 수신 후 기본 고소 일정 2건이 `중지 검토 (강풍)`으로 표시되는지 확인합니다.
- API 실패: 인터넷을 끊고 새로고침해도 일정이 보이고, 실패 안내와 `날씨 확인 전`이 표시되는지 확인합니다. 실내는 항상 `영향 없음`입니다.
- 강풍 테스트도 API 수신이 필요하며, 실패한 지역의 날씨를 임의로 만들지 않습니다.

## 일정 데이터 확인
- ‘오늘 판단 md로 저장’을 누르면 현재 표를 `현장일정_판단_YYYY-MM-DD.md`로 다운로드합니다. 마지막 줄에는 판단 기준이 포함됩니다. 날씨 수신 전에는 표에 보이는 `날씨 확인 전`을 그대로 저장하며, 강풍 테스트 중에는 테스트 결과임을 표시합니다.
- 일정 조회와 추가는 Supabase `wx_tasks`만 사용합니다. 기존 브라우저 `wx_added`는 자동 이전하지 않으며 삭제하지도 않습니다.
- T-01: SQL 실행 후 기본 일정 6건을 확인합니다.
- T-02: 일정을 추가하고 새로고침 및 다른 브라우저에서 같은 일정이 보이는지 확인합니다.
- T-06: SQL Editor에서 허용 목록 밖의 지역·구분을 넣으면 CHECK 제약조건으로 거부되는지 확인합니다.

## Supabase 설정 (F-06)
1. Supabase 프로젝트의 SQL Editor에서 이 프로젝트 루트의 `setup.sql` 전체를 실행합니다. 빈 표에만 가상 일정 6건을 넣으며 재실행 시 중복 삽입하지 않습니다.
2. `config.js`에는 프로젝트 URL과 공개용 publishable 키를 설정했습니다. secret/service_role 키를 넣지 마세요.
3. 배포 후 새로고침합니다. 연결 실패 시 화면 안내를 확인하세요. 실패한 저장은 입력값을 유지하며, 재시도 전 새로고침으로 등록 여부를 확인합니다.
4. 공개 교육용 표이므로 링크를 아는 사람이 조회·추가할 수 있습니다. 수정·삭제 권한은 주지 않습니다. 실제 개인정보는 저장하지 마세요.

외부 스크립트는 [공식 supabase-js CDN](https://supabase.com/docs/reference/javascript/installing) 하나만 사용합니다. 기상청 키는 계속 Vercel 서버 환경변수에만 둡니다.
